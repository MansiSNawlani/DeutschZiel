# Project Plan

> Generated by `/adopt` from the existing codebase plus the intent already
> recorded in `CONTEXT.md`, `project-list.md` and `docs/adr/0001-v0-v1-split.md`.
> Those three files remain the deeper source; this is the Blueprint-shaped
> summary the workflow reads. Sections 1-9 describe **v0**, the five-week
> personal tool, because that is what is being built now. v1 stays in
> `project-list.md` and is summarised in the build plan's frozen block.

## 1. Problem - What problem are we solving?

Preparing for the Goethe-Zertifikat B1 means bouncing between a coursebook, a
word list, sample papers, YouTube and a general-purpose chatbot, none of which
knows what the learner keeps getting wrong. The specific gap v0 closes is
**Schreiben and Sprechen practice with feedback that is scored the way the exam
is scored** (Erfüllung, Kohärenz, Wortschatz, Strukturen), corrected at the
learner's own level rather than rewritten in C1 German, and recorded so that
recurring Mistake patterns become visible instead of being forgotten.

The failure mode the project explicitly guards against is recorded in ADR 0001:
building the app feels productive enough to replace studying. v0 is capped at
roughly six hours of work for that reason. **Building is not studying.**

## 2. Users - Who is this for?

- **v0:** the author alone, sitting Goethe-Zertifikat B1 in roughly five weeks.
- **v1:** a closed, manually invited group of friends sitting Goethe or telc
  B1/B2 in 2027. No public sign-up.

Throughout the code and docs this person is the **Learner** (see `CONTEXT.md`),
never "user" or "student".

## 3. Features - What does the MVP need?

Already built:

- Schreiben practice: pick or generate a Goethe B1 Teil 1-3 Aufgabe, write it
  under a timer with a keystroke-persisted draft, and get Feedback.
- Tiered correction: Correct, Simpler and More advanced rewrites, plus per
  criterion bands and individual Mistake instances tagged from a closed Error
  category list.
- Sprechen Teil 2: the five-Folie presentation, recorded in the browser and
  assessed from the audio.
- Attempt journal: every Attempt written to disk as Markdown, with Mistake
  pattern counts read back across Attempts.
- Settings: bring-your-own Gemini key, runtime model discovery, Wortliste
  toggle, journal folder selection.

Still open for v0: see `build-plan.md`.

## 4. Data - What are we storing?

No database. v0 stores:

- **Settings** in `localStorage`: the learner's own Gemini API key, chosen model
  id, and the Wortliste toggle.
- **Draft** in `localStorage`: the in-progress Task and text, saved on every
  keystroke so a reload cannot cost a timed Aufgabe.
- **Attempts** as Markdown files in `journal/`, written through the File System
  Access API. `journal/` is gitignored because the repository is public and
  these are personal writings.
- **Static data in the repo:** the Goethe B1 Wortliste (2740 headwords) as JSON,
  the closed Error category taxonomy, and seed Tasks and Sprechen topics.

## 5. Tech - What stack are we using?

- **App:** Expo 57 with expo-router, React Native 0.86, React 19, TypeScript in
  strict mode. npm, with `package-lock.json` committed.
- **Platform reality:** although Expo targets iOS, Android and web, v0 runs
  **web only**. Recording uses `MediaRecorder`, the journal uses the File System
  Access API (Chromium only), and settings use `localStorage`.
- **Model:** Gemini, called over REST straight from the browser using the
  learner's own key. Model ids are discovered at runtime rather than hardcoded,
  because Google's free-tier lineup changes often.
- **No backend, no database, no accounts, no retrieval.** This is deliberate,
  not debt. See ADR 0001.

## 6. Monetize - How will this make money?

It does not. v0 is a personal study tool; v1 is for a closed group of friends.
There is no licensing, monetization or GDPR programme in scope. The only cost
model that matters is staying inside Gemini's free tier, which is why the
Wortliste can be switched off when per-minute token limits bite.

## 7. UI/UX - How should this look and feel?

The interaction loop is the same everywhere: **Aufgabe, Antwort, Korrektur,
Erklärung, weiter.**

- Screen chrome and task content are in German; explanations of mistakes are in
  English, so the learner reads the rule in a language they already have.
- Colour carries meaning rather than decoration. The palette in
  `src/constants/theme.ts` is semantic: success is the Correct tier and a full
  band, primary is the Simpler tier and anything navigable, accent is the More
  advanced tier, warning is over time or over length, danger is a Mistake
  instance or a failing band. Nothing gets an accent purely for looks.
- Feedback leads with the criterion bands, because with an exam close those show
  where marks are leaking fastest; the tiered rewrite sits below as the slower,
  better learning artifact.
- Light and dark are both first class, following the system scheme.
- Long waits are shown with an elapsed counter rather than a bare spinner, since
  a slow free-tier response cannot otherwise be told apart from a hang.

## 8. Deployment - Where and how will this ship?

**v0 is not deployed.** It runs locally with `npx expo start --web`. The app
must never be deployed with a Gemini key baked in; the bring-your-own-key design
exists precisely so that no server holds a secret.

v1's hosting decisions are already made and recorded in ADR 0001: Google Cloud
Run for the API, Supabase free tier for Postgres and pgvector, the paid Gemini
tier once other people's data is involved, and magic-link auth against a manual
allowlist.

## 9. Usage model and constraints (optional)

- **Scale:** one learner in v0; roughly five to fifteen in v1.
- **Operation:** local only in v0. Not internet-facing, no deployment.
- **Trust:** single trusted user running the app against their own API key. No
  multi-tenancy, no adversarial input, no shared persisted data.
- **The one real constraint:** the API key lives in the browser and must never
  be committed or bundled. `journal/` and `Resources/` are gitignored, the first
  because the writings are personal and the repository is public, the second
  because the coursebook PDFs are copyrighted and are not redistributed.
- **Explicit non-requirements for v0:** auth, multi-user support, a database,
  retrieval, compliance, availability targets, and native iOS or Android builds.
